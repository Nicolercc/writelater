You are acting as a Staff+ frontend engineer, senior product designer, and consumer-app UX lead.

We are building the front-end shell for a mobile-first planning app called **WriteLater**.

Product premise:
WriteLater is not a generic task app. It is a calm mobile companion for people who love physical paper planners but do not always carry them. The app helps users quickly capture tasks, events, notes, errands, ideas, money reminders, travel thoughts, and reflections while away from their physical planner. Later, it organizes those captures into a “Planner Update Ritual” so the user knows exactly what to copy into their paper planner.

The app should feel:

* calm
* beautiful
* fast
* intentional
* soft but not childish
* premium but not overdesigned
* smarter than a spreadsheet
* more emotionally gentle than Todoist
* more focused than Notion
* more tactile/planner-inspired than a normal productivity app

This first build is only the **frontend shell**. No backend yet. Use clean mock data and local component state where needed.

Tech stack:

* React
* TypeScript
* Vite if available
* Tailwind CSS
* shadcn/ui if available
* lucide-react icons
* Framer Motion if available
* local mock data in a dedicated file
* mobile-first responsive design

Do not build authentication yet.
Do not build a database yet.
Do not build AI yet.
Do not build a generic calendar app.
Do not build a CRUD-heavy dashboard.

The goal is to create a polished app shell that could be demoed in a portfolio presentation.

Core user:
A person who likes physical planners, handwritten organization, stationery, and intentional routines, but needs a lightweight mobile capture system when they are away from their planner. They may be a student, worker, creator, traveler, busy woman, or someone who gets overwhelmed when life details live only in their head.

Core jobs-to-be-done:

1. When I remember something while away from my planner, I want to capture it quickly so I do not lose it.
2. When I get home, I want to know exactly where each item belongs in my paper planner.
3. When I feel overwhelmed, I want the app to gently organize my scattered thoughts without making me feel behind.
4. When I review my day or week, I want a ritual that helps me transfer only what matters.

Main navigation:
Use a bottom tab bar on mobile with 4 tabs:

1. Capture
2. Inbox
3. Ritual
4. Planner

Desktop can center the mobile app frame or expand gracefully, but the primary experience should feel like a beautiful iPhone app.

Visual direction:
Use a warm paper-inspired design system.

Suggested palette:

* Background: warm ivory / parchment
* Cards: soft cream / off-white
* Text: deep espresso / charcoal
* Muted text: warm gray
* Accent: dusty rose, muted terracotta, or soft sage
* Secondary accent: pale lavender or butter yellow
* Borders: subtle beige
* Success: soft green
* Warning/urgent: muted clay red, never aggressive bright red

Typography:
Use clean, modern typography.
Create a hierarchy:

* App title: elegant and calm
* Section headings: medium weight
* Body text: readable
* Labels: small, soft, uppercase or letter-spaced only where tasteful

Overall design:

* Rounded cards
* Soft shadows
* Plenty of breathing room
* Subtle dividers
* No harsh black borders
* No neon colors
* No dense enterprise UI
* Use microcopy that feels human and supportive
* Use small planner-like details: “Today’s page,” “Weekly spread,” “Monthly view,” “Notes page,” “Write later”

Information architecture:
Create these primary screens:

SCREEN 1: Capture

Purpose:
The fastest possible place to dump a thought.

Layout:

* Warm header with greeting: “What do you need to write later?”
* Subtext: “Capture it now. Place it beautifully later.”
* Large input card with textarea.
* Placeholder examples rotating or listed subtly:

  * “Pay Chase by Friday”
  * “Ask about the presentation”
  * “Buy travel adapter before Spain”
  * “Reflection: I felt scattered after work”
* Optional quick chips below input:

  * Task
  * Event
  * Note
  * Errand
  * Money
  * Travel
  * Reflection
* Optional timeframe chips:

  * Today
  * Tomorrow
  * This Week
  * Later
* Primary button: “Save to Inbox”
* Secondary small action: “Clear”
* After save, show a soft confirmation toast or inline message:
  “Saved. We’ll help you place it later.”

Capture screen should prioritize speed. It should not ask too many questions upfront.

SCREEN 2: Inbox

Purpose:
A calm holding area for everything captured away from the physical planner.

Layout:

* Header: “Inbox”
* Subtext: “Unsorted thoughts waiting for planner time.”
* Search/filter row or simple filter chips:

  * All
  * Today
  * This Week
  * Later
  * Needs placement
* List of capture cards.
  Each card should show:

  * item title
  * optional original note
  * type badge
  * suggested planner destination
  * urgency/timeframe
  * small action buttons: “Place,” “Done,” “Later”
* Empty state:
  “Nothing waiting. Your planner brain is clear.”
* Use mock data with at least 8 realistic items:

  1. “Pay Chase card before Friday” / Money / Weekly spread
  2. “Ask manager about leaving by 1 PM” / Work / Today’s page
  3. “Buy Spain travel adapter” / Travel / Weekly spread
  4. “Review CarbonShift map branch” / Project / Today’s page
  5. “Look up free sewing classes” / Personal / Notes page
  6. “Call Mom about Healthfirst” / Family / Today’s page
  7. “Write down trip outfits” / Travel / Notes page
  8. “Reflection: I feel better when things have a place” / Reflection / Notes page

SCREEN 3: Ritual

Purpose:
This is the signature feature. It should feel like a quiet planner update session.

Layout:

* Header: “Planner Update Ritual”
* Subtext: “A few minutes to move life from your phone back onto paper.”
* A progress card:

  * “8 items captured”
  * “5 ready to write”
  * “3 can wait”
* A beautiful checklist grouped by planner destination:

  * Write on today’s page
  * Add to weekly spread
  * Add to monthly view
  * Add to notes page
  * Let go / archive
* Each group should have cards with checkboxes.
* Include a “Start ritual” or “Begin review” button.
* Include a “Copy summary” button that visually suggests the user can copy the organized summary into their planner.
* Include supportive microcopy:
  “You do not have to plan your whole life. Just give each thought a place.”
* Use gentle animation when checking items if Framer Motion is available.

SCREEN 4: Planner

Purpose:
A paper-planner-inspired preview of where items belong.

Layout:

* Header: “Planner”
* Subtext: “Your digital staging area before ink.”
* Tabs or segmented control:

  * Today
  * Week
  * Month
  * Notes
* Today view:

  * A paper-like card titled “Today’s Page”
  * Sections:

    * Top 3
    * Appointments
    * To Write
    * Notes
* Week view:

  * Paper-like weekly spread with days as columns/cards
  * Keep it simple and mobile-friendly
* Month view:

  * Minimal calendar-style grid or monthly list
* Notes view:

  * Soft note cards grouped by topic
* This screen should not become a full calendar app. It is a staging preview for the physical planner.

Data model:
Create TypeScript types:

CaptureItem:

* id: string
* title: string
* note?: string
* type: "task" | "event" | "note" | "errand" | "money" | "travel" | "reflection" | "project" | "family" | "personal" | "work"
* timeframe: "today" | "tomorrow" | "this-week" | "later"
* plannerDestination: "today-page" | "weekly-spread" | "monthly-view" | "notes-page" | "archive"
* status: "inbox" | "placed" | "done" | "later"
* createdAt: string
* isUrgent?: boolean

PlannerDestination labels:

* today-page: “Today’s page”
* weekly-spread: “Weekly spread”
* monthly-view: “Monthly view”
* notes-page: “Notes page”
* archive: “Let go”

Interaction requirements:

* Bottom navigation should switch screens without routing complexity unless routing is already available.
* Capture form should allow typing an item and saving it into local state.
* Newly saved items should appear in Inbox.
* If user chooses chips, the new item should use those values.
* If no chip is chosen, default type should be “note,” timeframe “later,” destination “notes-page.”
* Inbox item actions can update local status.
* Ritual screen should group current items by plannerDestination.
* Planner screen should show mock items grouped into Today, Week, Month, Notes.
* Keep all state lightweight and readable.

UX best practices:

* Do not overload the user on capture.
* Progressive disclosure: capture first, organize later.
* Keep the primary action obvious.
* Use plain language, not productivity jargon.
* Avoid shame-based wording like “overdue” or “failed.”
* Use softer wording like:

  * “Needs a place”
  * “Write later”
  * “Can wait”
  * “Ready for planner time”
* Make empty states feel relieving, not boring.
* Make the Ritual screen feel like the differentiator.

Accessibility:

* Ensure good color contrast.
* Buttons should have clear labels.
* Inputs should have labels.
* Focus states should be visible.
* Tap targets should be mobile-friendly.
* Avoid tiny text for important actions.

Responsive behavior:

* Mobile first.
* On desktop, center content in a max-width container around 430px to preserve app feel.
* Body background can show a warm gradient or paper texture-inspired solid color.
* App should feel like a polished mobile product, not a web admin panel.

Animation:
Use subtle animations only:

* screen fade/slide transitions
* card hover on desktop
* button press feedback
* checklist item completion
  No distracting motion.

Acceptance criteria:

1. App runs without errors.
2. The interface has four working tabs: Capture, Inbox, Ritual, Planner.
3. User can add a new capture item.
4. New item appears in Inbox.
5. Inbox has realistic mock items.
6. Ritual groups items by planner destination.
7. Planner screen has Today, Week, Month, Notes views.
8. UI feels calm, premium, mobile-first, and paper-planner-inspired.
9. Code is clean, typed, and componentized.
10. No backend, auth, or external API is included.
11. The result is polished enough to screenshot for a portfolio case study.

Important product warning:
Do not let this become a Todoist clone.
Do not make the app feel like corporate productivity software.
The emotional promise is:
“Capture now. Write it beautifully later.”

Build the frontend shell with strong product taste, clean architecture, and reusable components.
